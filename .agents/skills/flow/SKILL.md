# 파이프라인 — 기획부터 PR까지

각 단계 스킬을 **순서대로** 호출하는 오케스트레이터다. 규칙은 각 스킬이 갖고 있으므로
여기서는 **순서·게이트·중단 조건**만 관리한다.

```
① /plan      요구사항 → MVP 대조 → 이슈           [게이트] 이슈 번호
② /design    도메인·계층 배치 설계                 [게이트] 사용자 승인
③ /implement 브랜치 + 코드 + 테스트                [게이트] 빌드 통과
④ /review    셀프 리뷰 (병렬 서브에이전트)          [게이트] [필수] 0건
⑤ /commit    한글 컨벤션 커밋                      승인 없이 진행
⑥ /pr        푸시 + draft PR 생성                  승인 없이 진행
```

**⑤·⑥은 사전 승인을 받지 않는다.** 커밋 메시지와 PR 본문은 만든 뒤 보고에 담는다.
안전장치는 승인이 아니라 훅과 게이트다 — `.githooks/`의 pre-commit·commit-msg,
`harness/hooks/core/git_guard.py`, 그리고 ④의 `[필수]` 0건 게이트.

**PR은 항상 draft로 열린다.** `gh pr ready`를 실행하지 않는다 —
리뷰를 받을 준비가 됐다는 판단은 사람이 한다.

이후 흐름은 사람이 개입한다 — 리뷰 코멘트가 달리면 `/pr-feedback`, 남의 PR은 `/pr-review`.

## 시작 위치 판단

인자를 보고 어디서 시작할지 정한다. **이미 끝난 단계를 다시 하지 않는다.**

| 인자 | 시작 |
| --- | --- |
| 요구사항 문장 | ① `/plan` |
| 이슈 번호 (`/flow 12`) | ② `/design` |
| 인자 없음 | `git status`·`git branch`로 현재 상태를 보고 판단 후 사용자에게 확인 |

## 게이트 — 통과 못 하면 멈춘다

**게이트에서 멈추는 것이 이 스킬의 핵심이다.** 조용히 다음 단계로 넘어가지 않는다.

| 게이트 | 통과 조건 | 실패 시 |
| --- | --- | --- |
| ① → ② | 이슈가 생성되고 번호를 받음 | P1 판정이면 **여기서 종료.** 구현하지 않는다 |
| ② → ③ | 사용자가 설계서를 승인 | 설계 수정 후 재승인. 승인 없이 코드를 쓰지 않는다 |
| ③ → ④ | 빌드·린트 통과 | 실패 원인 수정. `gradlew`가 없으면 "미검증"으로 명시하고 진행 |
| ④ → ⑤ | `[필수]` 0건 | 수정 후 리뷰 재실행. `[필수]`를 남긴 채 커밋하지 않는다 |
| ⑤ → ⑥ | 커밋 훅 통과 | 훅 실패 시 **`--no-verify`로 우회하지 않는다.** 원인을 고친다 |
| ⑥ 완료 | draft PR 생성 | rebase 충돌·시크릿이면 중단하고 알린다 |

## 즉시 중단하는 조건

아래를 만나면 **다음 단계로 가지 말고 사용자에게 묻는다.**

- **P1 기능** (`AGENTS.md` §3 하단 목록) — 구현 대상이 아니다
- **새 도메인이 필요** — 도메인 분할은 미확정이다(`docs/architecture.md` §11)
- **`docs/architecture.md` 규칙과 충돌하는 요구사항** — 코드로 우회하지 않는다.
  규칙이 불편하면 문서를 고치는 PR을 올리는 게 팀의 방법이다(`CONTRIBUTING.md` §8)
- **rebase 충돌**
- **시크릿이 변경에 포함됨**
- **미확정 사항**(코루틴 범위, 검증 태스크)에 걸리는 판단

## 진행 관리

- 6단계를 **TaskCreate로 등록**하고 단계마다 상태를 갱신한다. 사용자가 어디까지 왔는지 봐야 한다.
- 각 단계 종료 시 **한 줄 요약**을 남긴다. 단계 전체 로그를 다시 뱉지 않는다.
- 서브에이전트 결과는 **요약해서 전달**한다. 사용자에게 원문이 그대로 보이지 않는다.

## 하지 않는 것

- **병합하지 않는다.** 리뷰어 승인이 필요하다(`CONTRIBUTING.md` §4). draft PR 생성이 종착점이다.
- **draft를 해제하지 않는다.** `gh pr ready`는 사용자의 몫이다.
- 게이트를 건너뛰지 않는다. ⑤·⑥의 사전 승인만 생략하고, ①~④의 게이트는 그대로다.
- 커밋 훅을 `--no-verify`·`SKIP_HOOKS=1`로 우회하지 않는다.
- 한 번에 여러 이슈를 처리하지 않는다. 이슈 하나 = PR 하나다.

```
④ 리뷰   [필수] 2건 수정 완료, [제안] 1건 미반영(사유: …)
⑤ 커밋   3개 (feat 2, test 1)
⑥ PR     #34 (draft) https://github.com/Nexters/ALIGNER-SERVER/pull/34

미검증: 통합 테스트 (Docker 미실행)
남은 것: GitHub에서 "Ready for review"를 눌러 draft를 해제하면 리뷰 요청됩니다
```
